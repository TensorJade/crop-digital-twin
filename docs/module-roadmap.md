# 模块开发计划

首版面向华南水稻，按农田管理、模型计算、地图、遥感和发布运维依次开发。前后端保持单仓库，模块内部集中业务规则，模块之间通过明确的接口交换数据。

| 模块 | 主要内容 | 依赖 | 状态 |
|---|---|---|---|
| M1 农田管理 | 地块、种植季、农事和修订历史 | 开发环境 | 完成 |
| M2 账户与授权 | 登录、组织、角色、成员管理和审计 | M1 | 完成 |
| M3 模拟输入与作物引擎 | 参数、天气、输入快照、PCSE 和计算任务 | M1、M2、作物参数 | 部分完成 |
| M4 地图与长势 | 卫星底图、圈地、面积、矢量和时间回放 | M1、M3 | 未开始 |
| M5 无人机观测 | 影像导入、质控、反射率和 LAI 反演 | M1、传感器资料、样本 | 未开始 |
| M6 模型更新 | 观测匹配、参数校准、误差分析和重算 | M3、M5 | 未开始 |
| M7 发布与运维 | 任务恢复、备份恢复、安全、容量和试点验收 | 业务模块 | 未开始 |

M3.1 的输入与快照、M3.2 的潜在生长计算、M3.3 的历史网格天气、长季分段和站点目录已完成。授权站点观测、移栽水田适配和实测验证仍需开发。最近检查结果见 [开发进度](progress.md)，各次修改见 [开发日志](dev-log/README.md)。

## 模块完成条件

开发前明确用例、支持范围和接口；开发后检查正常操作、异常处理、持久化及模块间交互。接口变化同步到契约，检查结果写入日志，并更新需求和进度记录。软件测试、页面验收和农艺验证分别记录。

## 实现约定

- 使用一个模块化后端、一套前端和一份业务数据库，暂不拆分微服务。
- 接口处理输入输出和授权，应用层组织业务与事务，领域层保存规则，存储层实现 SQL。
- 在数据库、密码库、天气服务和算法进程等依赖处定义接口，避免增加通用 CRUD 框架、事件总线和未使用的中间件。
- 组织内共享地块，采用管理员、农田管理、只读三种角色。逐成员地块授权、公开注册和账号找回另行安排。
- 农事按发生日期记录，修正时新增版本，保留原记录供模拟快照引用。
- 计算使用 SQL 任务表和独立 worker。出现容量或协调需求后，再评估 Redis。
- 页面使用亩、播种、移栽、灌溉、施肥等名称，内部按标准单位保存。

## 试点资料

已确定作物为水稻、地区为华南，具体县市、品种参数和授权站点数据源尚待确定。目前天气来自 NASA 公开历史网格资料。模型可计算资料完整的直播潜在生长，但贮藏器官干物质尚不能换算为当地实收产量。移栽、育苗和灌排的日期及管理规则将在水稻适配阶段补充。
