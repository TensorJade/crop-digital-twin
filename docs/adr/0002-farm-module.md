# ADR 0002：最小农田管理模块

日期：2026-10-08。依据：用户要求按模块实施、奥卡姆剃刀、高内聚低耦合；首版华南水稻。

- 将地块、种植季和农事集中为农田管理上下文。HTTP、业务和持久化职责分层，不创建三个微服务或通用 CRUD 框架。
- 使用一个 FarmRepository Protocol 隔离 SQL，原因是当前确有 SQLite 本地和 PostgreSQL 两个存储环境，不为假想实现增加抽象。
- SQLite 便于本机直接开发；PostgreSQL 是服务器目标。共用 SQLAlchemy 与 Alembic，使用真实迁移和数据库集成测试，不以 SQLite 结果证明 PostgreSQL 已通过。
- 采用逻辑外键规则；应用事务检查引用、限制删除、约束修订指针，并在 PostgreSQL 使用行锁。外部 SQL 绕过应用仍可能破坏关系，后续运维须限制写权限与核对数据完整性。本 ADR 解决 M1 的建表选择，不宣称所有未来表已决策或审批。
- ID 使用 UUID，关系字段同类型；这是本模块分布式 ID 的具体选择。
- 人工面积和位置作为初值记录；不引入 GIS 库或地图 SDK。空间计算在地图模块内实现并验证。
- 原始农事和修正版本都留存，单位换算纯函数可单独验证；不引入尚未使用的 Redis 或消息队列。
- 前端只使用 Vue 局部状态和模块组件；没有跨页面共享状态需求时不加入 Pinia/Router。
- 无账户权限时仅支持本地单用户操作，拒绝 production 环境启动。生产能力在 M2 完成后另行验收。
